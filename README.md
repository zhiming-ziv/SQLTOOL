# SQLTool — 数据库工作台

参照 **SQL Server Management Studio** 界面构建的数据库管理工具，支持 **SQLite / MySQL / PostgreSQL / SQL Server**。

它有两种截然不同的引擎接入方式，理解这一点很重要：

| 方式 | 引擎 | 是否需要后端 | 数据在哪里 |
|---|---|---|---|
| **浏览器内引擎** | SQLite（WebAssembly） | 不需要 | 浏览器 IndexedDB / 本机文件 |
| **服务器代理引擎** | MySQL / PostgreSQL / SQL Server / 服务器端 SQLite | **需要** `node server.js` | 真实的数据库服务器 |

> **为什么远程数据库一定要后端？**
> 浏览器的安全模型不允许网页打开原始 TCP 连接，所以**任何"纯前端"方案都无法连接远程数据库服务器**。
> 本项目对 SQLite 的做法是把引擎本身编译成 WebAssembly 放进浏览器里跑（SQL 真的在执行，不是模拟）；
> 对 MySQL / PostgreSQL / SQL Server 则引入一个**只监听 `127.0.0.1`** 的本地代理进程，由它代替浏览器去连数据库。

## 快速开始

### 1. 安装依赖（连接远程数据库时必需）

```bash
npm install          # 安装 mysql2 / pg / mssql
```

不装也能用 —— 只是远程驱动会显示为「缺失」，浏览器内 SQLite 不受影响。

### 2. 启动本地服务

```bash
node server.js              # 默认 8777 端口
node server.js 8888         # 自定义端口
```

Windows 上也可以直接双击 `start.bat`。

启动后终端会打印可用/缺失的驱动：

```
  工作台   http://127.0.0.1:8777/app/index.html
  引擎自检 http://127.0.0.1:8777/app/selftest.html
  界面演示 http://127.0.0.1:8777/demo/index.html

  可用驱动 MySQL / MariaDB / PostgreSQL / SQL Server / SQLite（服务器本地文件）
```

### 3. 打开工作台

<http://127.0.0.1:8777/app/index.html>

> **必须通过本地服务器访问，不能直接双击 HTML 文件。**
> 浏览器要求 WebAssembly 与 IndexedDB 运行在 `http://` 协议下，`file://` 会被安全策略拦截。

## 功能

### 连接管理
- 一个对话框里可选 **5 种连接类型**：

  | 类型 | 说明 |
  |---|---|
  | SQLite（浏览器内） | 默认。可新建空库，或打开本机 `.db` 文件；数据存 IndexedDB |
  | SQLite（服务器文件） | 打开运行 `server.js` 那台机器上的 `.db` 文件，适合大文件，无需上传 |
  | MySQL / MariaDB | 通过 `mysql2` 连接，默认端口 3306 |
  | PostgreSQL | 通过 `pg` 连接，默认端口 5432 |
  | SQL Server | 通过 `mssql`(tedious) 连接，默认端口 1433，可选强制加密 |

- **测试连接** 按钮：不建立会话，先验证主机 / 账号 / 库是否可达
- **最近连接** 快捷区：一键重连历史连接（密码存在服务端，不会回传前端）
- 查询在发起时保存连接和数据库；执行期间切换连接或数据库，返回的结果仍属于原目标。
  当前目标与结果来源不一致时，网格显示来源提示并隐藏编辑入口；同一标签页的旧响应不会覆盖新查询结果
- 编辑、插入和删除沿用原结果的连接、数据库及行定位信息；确认期间切换界面不会改变操作目标。
  原连接/标签页已关闭、正在重新查询或结果已变化时，旧编辑操作会被拒绝
- 从连接右键菜单导出数据库时，导出被右键点击的连接

### 对象资源管理器（左侧）
- 读取**真实 schema**：表、视图、索引、触发器、**存储过程、函数**及其列定义
- 存储过程 / 函数文件夹按类型分开显示（SQL Server 会标出标量函数 / 内联表值函数 / 表值函数 / 聚合函数）；
  PostgreSQL 的同名重载函数带上参数签名，避免列表里出现一串看不出差别的同名项
- **双击存储过程 / 函数即可查看定义原文**（也可右键 →「查看定义」），弹窗内可一键复制或插入到查询窗口。
  定义是**按需读取**的——一个库里几百个存储过程很常见，一次性把 CREATE 原文全拉回来既慢又占内存
- 右键 →「生成调用脚本」按方言生成 `EXEC` / `CALL` / `SELECT * FROM` 骨架
- 多数据库浏览：顶部数据库切换器可切换库（MySQL 用 `USE`，PostgreSQL 每库独立连接，SQL Server 每库独立连接池）
- 浏览器内 SQLite 的表节点显示统计行数；远程驱动可提供估算行数（以 `~` 标记）。
  **服务端 SQLite 加载对象树时不扫描行数**，可右键表 →「统计精确行数」按需查询，结果显示在提示中
- 每个列节点显示类型、主键、NOT NULL
- 列定义**懒加载**：展开表节点时才去查列，避免大库卡顿
- 顶部搜索框实时过滤对象与列名
- 右键菜单随对象类型变化：查看 DDL、生成 SELECT / CREATE / INSERT 脚本、导入导出、清空、删除

### 查询编辑器（右上）
- 多标签文档窗口，SQL 语法高亮 + 行号
- **选取执行** —— 编辑器里有选区时，`F5` / `Ctrl+Enter` / 工具栏「执行」**只运行选中的部分**，
  没有选区才执行整篇（与 SSMS 一致）。调试长脚本时不必把不想要的语句删掉。
  有选区时工具栏按钮会点亮并变为「执行选中」，结果面板也会注明「只执行了选中的 N 行，其余未执行」
- **输入提示（自动补全）** —— 边打边提示，不用记表名列名
  - 打关键字前缀（如 `SEL`）→ 提示 SQL 关键字与函数
  - 在 `FROM` / `JOIN` / `INTO` / `UPDATE` / `TABLE` 之后打空格 → 只提示库里的表与视图
  - 打 `表名.` 或 `别名.` → 只提示该表的列（会解析 `FROM employees e` 这样的别名）
  - **列提示被限定在当前语句用到的表里**：`SELECT * FROM 表A WHERE 前缀` 只会给出表A的列，
    不会冒出库里其他表的列，也不会把表名混进条件里。提示头部会标明作用域，例如
    `本语句表列 · 表A`。只有在还没写 `FROM` 时（比如刚开始写 `SELECT`）才放宽到全库对象。
  - 支持 SQL Server 风格的方括号前缀：打 `[fI` 会补成 `[fID1]`（自动闭合）
  - `↑` `↓` 选择，`Enter` / `Tab` 补全，`Esc` 关闭；`Ctrl+Space` 随时手动唤出
  - 关键字补全为大写，表名/列名保持原样（避免破坏区分大小写的库）
- 支持多语句脚本一次执行（分号切分，正确跳过字符串 / 行注释 / 块注释 / 引号标识符）
- 真实错误消息（来自数据库引擎本身）
- `EXPLAIN QUERY PLAN`（SQLite）/ `EXPLAIN` 显示真实执行计划

### 结果网格（右下）
- 表头点击排序；单击选中行，`Ctrl` 加选、`Shift` 连选（支持多行）
- 一键导出 CSV / JSON / 复制
- NULL / 数字 / BLOB 分别渲染

**增删改（双击表名打开数据后即可编辑）**

| 操作 | 入口 | 说明 |
|---|---|---|
| **改** | 双击单元格 | 输入后 `Enter` 提交，`Esc` 取消；空字符串写入 NULL |
| **增** | 结果面板右上「＋ 新增行」/ 右键「新增行…」 | 按真实表结构生成表单，标注主键 / 自增 / 必填；自增列留空即自动生成，参数化 INSERT |
| **删** | 「－ 删除行」/ 右键「删除选中行」 | 删除所有选中行，执行前二次确认 |

**行定位策略**（决定 UPDATE / DELETE 能否精确命中目标行）：

| 优先级 | 适用 | 做法 |
|---|---|---|
| 1 | 浏览器内 SQLite | 隐藏的 `rowid`（`SELECT rowid AS __rid, *`），最精确 |
| 2 | 有主键的表 | 用主键列拼 `WHERE` |
| 3 | **没有主键的表** | 退化为**按全部列的原值**拼 `WHERE`（与 SSMS 行为一致），NULL 列用 `IS NULL` |

> 第 3 条很重要：真实业务库（尤其 ERP）里没有主键的表很常见。
> 只认主键会导致整张表都改不了，而且界面上不会给出任何原因。
> 现在这种表可以正常增删改，面板上会提示「无主键，按全部列原值匹配」；
> 若表中存在**完全重复的行**，这些行会被一并修改/删除（会给出明确警告）。

### 数据导入导出
| 操作 | 说明 |
|---|---|
| 打开 `.db` / `.sqlite` | 校验 SQLite 魔数后真实打开 |
| 导入 `.sql` 脚本 | 读入编辑器并执行 |
| 导入 CSV 到指定表 | 自动匹配列名，事务批量插入 |
| 导出 `.db` | 导出完整数据库文件（仅浏览器内 SQLite） |
| 导出 CSV / JSON | 导出当前结果集 |

### 持久化
- 浏览器内数据库自动保存到 **IndexedDB**，刷新页面数据不丢
- 启动时自动恢复上次的连接
- 可在连接对话框中选择「仅本次会话」

## 技术说明

### 后端架构

```
浏览器  ──HTTP/JSON──▶  server.js (仅监听 127.0.0.1)
                            │
                            ├─ /api/connect    建立会话（返回 connId）
                            ├─ /api/query      执行 SQL
                            ├─ /api/schema     读取库/表/视图/索引 + 存储过程/函数列表
                            ├─ /api/columns    读取列定义
                            ├─ /api/routine-ddl 读取单个存储过程 / 函数的 CREATE 原文
                            ├─ /api/databases  列出可切换的库
                            ├─ /api/saved      已保存连接的增删查
                            └─ /api/disconnect 关闭会话
                            │
                            ▼
                     server/drivers.js
                            │
        ┌───────────┬───────┴────────┬──────────────┐
        ▼           ▼                ▼              ▼
     mysql2        pg             mssql        node:sqlite
   (MySQL)    (PostgreSQL)   (SQL Server)   (服务器本地文件)
```

驱动适配层对外是统一接口 `load / connect / query / databases / schema / columns / routines / routineDdl / close`，
前端 UI 完全不感知具体是哪种数据库。

MySQL 同一会话的操作串行执行，切库和随后的查询作为完整操作排队。
PostgreSQL / SQL Server 对同一会话、同一目标库的并发建连复用正在建立的连接；失败后可以重试。
关闭会话时会阻止新操作，并等待已排队的 MySQL 操作及正在建立的远程连接完成后回收资源。
这不提供跨 HTTP 请求的事务独占；需要连续执行的事务语句应放在同一次查询请求中。

服务端 SQLite 目前仍使用同步查询，慢 SQL 可能阻塞本地 HTTP 服务；本轮优化并未引入工作线程。

### 方言差异的处理

| 差异点 | 处理方式 |
|---|---|
| 占位符 | 前端统一写 `?`；PostgreSQL 转成 `$1,$2`，SQL Server 转成 `@p0,@p1` |
| 标识符引用 | MySQL 用 `` ` ``，SQL Server 用 `[]`，其余用 `""` |
| 分页语法 | SQL Server 用 `SELECT TOP n`，其余用 `LIMIT n` |
| 切换数据库 | MySQL 用 `USE db`（连接级状态）；PostgreSQL 每库开独立连接；SQL Server 每库独立连接池 |
| 行定位 | SQLite 用 `rowid`；有主键用主键列；**无主键退化为全列匹配** |
| 多语句 | MySQL 开启 `multipleStatements`；其余逐个语句执行 |
| 过程 / 函数列表 | MySQL `information_schema.ROUTINES`；PostgreSQL `pg_proc`（含 `prokind` 区分过程/函数/聚合）；SQL Server `sys.objects` 按 `type` 分类；SQLite 无此类对象 |
| 过程 / 函数定义 | MySQL `SHOW CREATE PROCEDURE/FUNCTION`（无权限时回退 `ROUTINE_DEFINITION`）；PostgreSQL `pg_get_functiondef(oid)`；SQL Server `sys.sql_modules.definition` |

### 安全设计
- 服务**只监听 `127.0.0.1`**，不对局域网暴露
- 校验 `Host` 请求头，拒绝非回环地址（防 DNS 重绑定攻击）
- 密码**永不回传前端**，列表里只显示 `••••••`
- `connections.json`（含保存的密码）与 `node_modules/`、`shots/` 均已加入 `.gitignore`

### 引擎版本
| 引擎 | 版本 | 说明 |
|---|---|---|
| SQLite（浏览器内，sql.js） | **3.45.2** | WebAssembly，完全内置，断网可用 |
| SQLite（服务器文件，node:sqlite） | 随 Node.js 版本变化 | Node 22.5+ 内置，零额外依赖；实际版本见连接状态 |

## 常见问题

### 连上了，但展开表报「用户 'xxx' 登录失败」
这是 **v1.0 已修复的缺陷**：早期版本把「数据库架构名」当成了「数据库名」传给后端
（SQL Server 的 `dbo`、PostgreSQL 的 `public`、SQLite 的 `main`），导致后端去连一个
名为 `dbo` 的库而登录失败。MySQL 因为它的 schema 就等于库名，所以不会暴露。

如果仍遇到，请确认已经拉取到修复版本；现在的错误消息会带上库名，例如
`无法连接数据库「CJERP1」：用户 'dberpus' 登录失败。` —— 这种就是真实的权限问题：
该登录名在目标库里没有对应用户，需要在 SQL Server 里执行
`USE CJERP1; CREATE USER dberpus FOR LOGIN dberpus;`（或授予相应角色）。

### 树里有这张表，执行却报 `Invalid object name 'xxx'`
三种常见原因：
1. **库不对**：界面显示的当前库与连接时填的库不一致。本工具已修复为「执行时始终带上界面上显示的当前库」。
2. **大小写敏感**：库排序规则是 `..._CS_...`（区分大小写）时，`portalusers` 与 `PortalUsers` 不匹配。
   请按树里显示的原样书写，或双击表名让工具自动生成带方括号的 SQL。
3. **默认架构不是 dbo**：未加架构前缀的 `portalusers` 会先按登录名的默认架构解析。
   写成 `dbo.PortalUsers` 即可。

### 单元格改不了 / 「新增行」「删除行」按钮不出现
这两个按钮**只在「从表打开的结果集」上出现**——也就是**双击左侧对象树里的表名**之后。
在查询窗口里手写 `SELECT * FROM t` 执行出来的结果，工具无法确认结果与表的对应关系，
所以按只读处理（避免误改到不该改的行）。

另外，如果表**没有主键**，旧版本会整张表都不可编辑且不给任何提示；
现在会退化为「按全部列原值匹配」，并在面板上显示 `无主键，按全部列原值匹配`。
如果该表存在完全重复的行，改一行会同时改到这些重复行，工具会明确警告。

### 输入提示没弹出来
- 补全只在**有前缀**时自动弹出；光标后什么都没有时按 `Ctrl+Space` 手动唤出。
- 表名 / 列名来自当前连接已加载的 schema。刚建完表请先点一下工具栏的**刷新**，
  让对象树重新读取结构，补全才有数据。
- 服务端文件 / 远程库的列定义是**展开表节点时才懒加载**的；没展开过的表也能补出列，
  前提是 schema 已经读到（刷新一次即可）。

### 条件提示里出现了别的表的列名
这是 **v1.3 已修复的缺陷**：早期版本的列提示取自「当前连接里所有表的全部列」，
所以在 `WHERE` 里打一个前缀，会把库里任意一张表的列都列出来。
现在列提示会**限定在当前语句的 `FROM` / `JOIN` 表**里，提示头部会写明作用域
（如 `本语句表列 · employees`）；`表名.` / `别名.` 也只给该表的列。
只有在语句里还没有 `FROM` 时（比如刚开始写 `SELECT`）才放宽到全库对象。

### 看不到存储过程 / 函数
- 对象树里的「存储过程」「函数」文件夹是**按当前连接已加载的 schema** 渲染的。
  刚连上时如果没看到，点一下工具栏**刷新**。
- **SQLite 没有存储过程与函数**这类服务端对象，所以浏览器内 SQLite 和服务端 SQLite 都不会显示这两个文件夹。
  这是 SQLite 本身的限制，不是工作台的缺陷。
- 列表是空的但库里有对象 → 多半是**当前账号没有读取系统表的权限**。
  此时表 / 视图照常显示，过程与函数静默留空（不会让整个结构读取失败）。
  需要 `information_schema.ROUTINES`（MySQL）、`pg_proc`（PostgreSQL）、
  `sys.objects` + `sys.sql_modules`（SQL Server）的可见权限。
- 双击节点后弹窗显示「读取失败」→ 通常是**没有查看定义正文的权限**。
  MySQL 需要 `SHOW VIEW` 或对象所有权，SQL Server 需要 `VIEW DEFINITION`。

### 执行时只想跑一部分语句
在编辑器里**选中要执行的部分**，再按 `F5`（或点「执行」）。有选区时只跑选区，没有选区才跑整篇。
选中后工具栏按钮会点亮并变成「执行选中」，结果面板也会注明「只执行了选中的 N 行，其余未执行」，
确认一下这个提示就知道是不是只跑了选区。

### 提示「无法连接本地后端服务」
`server.js` 没有运行，或端口不是 8777。执行 `node server.js` 后重新打开页面。

## 快捷键

| 按键 | 功能 |
|---|---|
| `F5` / `Ctrl+Enter` | 执行当前 SQL（**有选区时只执行选区**） |
| `Ctrl+F5` | 显示执行计划（同样遵循「有选区只跑选区」） |
| `Ctrl+N` | 新建查询窗口 |
| `Ctrl+O` | 打开数据库文件 |
| `Ctrl+S` | 保存到浏览器本地 |
| `Ctrl+W` | 关闭当前查询窗口 |
| `F8` | 显示/隐藏对象资源管理器 |
| `Tab` | 编辑器内插入 4 个空格 |
| `Ctrl+Space` | 手动唤出输入提示 |
| `↑` `↓` / `Enter` / `Esc` | 提示列表：移动 / 补全 / 关闭 |
| 双击表名 | 打开该表数据（进入可编辑模式） |
| 双击单元格 | 直接编辑并写回数据库 |
| `Ctrl` / `Shift` + 单击行 | 多选行，便于批量删除 |
